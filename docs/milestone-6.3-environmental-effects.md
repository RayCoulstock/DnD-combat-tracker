# Milestone 6.3 — Environmental effects

## Phase 0: repository audit and design

Audited against origin/main `6eefe9c` (Milestone 6.2 session rejoining), before implementation. Canonical UI source is `docs/ui/ui-design-guidelines-v2.1.md` and `feature-zone-matrix.md`; the unversioned guidelines file does not exist. Read the 6.0 lighting and 6.1 fog architecture, current shared schemas/domain, editor surfaces, GLB resource leases, lighting renderer and commands, server persistence/command execution and CI configuration.

### Architecture and extension points

BattleMap3D owns one demand-rendered R3F Canvas. BattlefieldScene translates visible floors with northwest alignment and feet / 5 elevation. DungeonBuilder owns D4 tools, C3 contextual forms and D3 history. CellEditorSurface already converts pointer coordinates, snaps placement and supports tap without interfering with middle/right camera controls. SharedModel3D/modelResources lease cached GLBs; effects must not alter these assets. Shared `readDungeon`, `dungeonLevels`, `composeLevels`, `levelDocument` and `editMap` are the persistence/multi-floor/history boundaries. Map commands execute through DM-authorized `applyMapEdit` and existing server transactions, command receipts and encounter/map revisions. Templates/import/export all use the same strict map schema. No database migration or alternate command channel is needed.

### State and registry

Optional document-level `environmentalEffects: {version: 1, effects: [...]}`. Absence remains absent on legacy maps. At most 64 stable-ID records, bounded finite position (grid anchor X/Z and heightFeet), yaw degrees, scale, enabled, intensity, speed, colour and opacity. Floor IDs and in-bounds anchors validate against the actual map. No renderer objects or particle positions persist. Foundation introduces a bounded magical-motes preset to exercise the engine; B and C add their libraries only in their own increments. Registry metadata defines category, description, icon, defaults, accepted parameter schema, renderer key, local quality budgets, conservative animated bounding radius, resources, light/attachment capabilities. Client renderer registry is separate from shared metadata; no executable user code is accepted.

### Rendering, lifecycle and quality

One shader-driven Points draw per effect with deterministic static seeds; no per-frame React state, allocations, geometry replacement or network commands. Each renderer uses Fiber's existing useFrame/invalidate scheduling and disposes owned geometry/material on replacement/unmount. Low/Medium/High reuse the existing local lighting-quality preference, with 12/32/64 particles per foundation effect. Reduced motion renders static particles and stops continued invalidation. Disabled effects unmount. Visible floor groups own resource lifetime, so floor/map switches release inactive resources. B adds billboard atmosphere/flame adapters; C adds reusable animated surfaces and bounded arc geometry, rather than a giant preset conditional.

### Lighting and fog security

A does not emit light. B must integrate optional emitters into existing map-owned lighting sources, with explicit ownership and atomic cleanup; no independent Three lights. D attachments must reuse stable scene-object IDs and existing transform conventions; missing targets disable effects until reattached, with no dangling runtime references. Linked lights must follow the same visibility decision as their effect and cannot be double-owned.

Server `playerDungeon` filters effect records before serialization. Only player-visible floors and fully revealed conservative animated support are eligible. Radius includes every animated particle at every yaw/scale and height (A uses a sphere bound). Support crossing map bounds is withheld while fog is enabled. No effect names/private metadata or attachment IDs are needed in A. Hidden records never reach player raycasting, inspectors, geometry or reconnect snapshots. This intentionally withholds an entire effect at a partial boundary rather than clipping its particles. Existing GLBs require full-floor revelation when trusted footprint bounds are unavailable. Previously delivered data cannot be revoked from a player's memory/cache. Visual concealment alone is not data secrecy. Later attachments require parent visibility filtering before this support test.

### Synchronization and resource limits

Existing DM-only map commands provide atomic set, duplicate and remove. Existing map history, server campaign/session authorization, stale-revision rejection, receipts, persisted snapshots and reconnect joins remain authoritative. Only configuration changes travel over Socket.IO. Animation is local deterministic presentation, with no per-frame writes. D lifecycle commands must stamp authoritative start/revision data on the server and reconstruct final state for late joiners. No combat, terrain, fog-mask or transition mutation is introduced.

### Performance targets and measurement

Targets, not measured guarantees: desktop ~16.7ms / 30 active effects; tablet ~33.3ms / 10–15. Test 12×12/5, 30×30/15 and 50×50/30 scenes (the actual repository limit is 50, so the requested 60×60 requires a separately scoped map-limit change). Include multiple floors and fog/lighting/GLBs. Record average and p95 frame intervals, renderer.info calls/triangles/points/memory before placement, after steady rendering and after deletion/map switch. Use browser instrumentation only in development/tests; physical tablet measurements remain separate from Chromium software rendering. Foundation cap: 4,096 points / 64 effects at High; each effect owns one bounded buffer/material. Distance/frustum scheduling improvements belong to D after measurement.

### Migration and rollback

Additive JSON only; existing encounter_maps/template/checkpoint storage and backups include effects. Legacy maps are not rewritten. Document-level effects must be stripped from floor geometry adapters and explicitly retained by composition. Floor deletion removes effects; duplication uses deterministic new IDs and enforces capacity atomically. Floor shrink rejects out-of-bounds effects until moved/deleted. Old strict binaries reject the new field: preserve exports and coordinate binary rollback; never silently strip persisted effects. No production data or deployment changes.

## 6.3B design — elemental and atmospheric effects

Starting from main `d293ca1` / merged PR #54. User confirms A is live; GitHub API remains Forbidden, so remote publication status is not independently observable. B remains a separate main-targeted increment; no deployment or C/D work.

Add four fire sizes, rising embers/falling sparks/electrical sparks, three smoke forms, three steam forms and three low mist forms. Shared optional bounded `parameters` cover density, particle lifetime, spread, vertical extent and X/Z drift; preset defaults leave A motes unchanged. Fire combines crossed animated flame surfaces with optional bounded embers (off at Low). Atmosphere uses instanced world-size billboards, deterministic seed attributes and shader motion; sparks share the bounded particle adapter. No textures, CPU particle simulation or per-frame React/network state. Low reduces counts and shader detail; all tiers share authoritative transforms/parameters. Steam short burst is a repeating short visual puff in B; DM-triggered one-shots belong to D.

Optional light is a stable reference from an effect to an ordinary persisted `lighting.sources` emitter. A dedicated atomic effect-light command creates/configures/removes it; effect duplication copies it, effect/floor deletion removes it, movement updates its floor/position, and whole-map undo restores both. Appearance is canonical in the emitter, so lighting scenes still capture and activate it. Ordinary source placement/attachment/duplicate/delete commands cannot take ownership of a managed effect light. Light enabled state remains independent; the renderer additionally gates it by effect enabled/intensity. Existing point budgets, flicker and shadow infrastructure apply; optional effect lights start without shadows and never mutate unrelated environment presets.

Player projection requires the complete conservative shader extent AND linked light radius to be revealed on an authorized floor. Withhold the whole effect/emitter at partial boundaries; no clipping/opacity workaround. Renderer bounds include all drift, rotated geometry, particle size and vertical extent. The shared visibility helper is reused for effects and owned light filtering. Players receive only authorized effect references and sources; hidden effect IDs never survive in light records. Linked sources remain ordinary permitted point lights after projection. Existing full-floor GLB policy is unchanged. Disabled/zero-intensity effects cannot leave active linked emitters, including during saved lighting transitions.

UI remains D4 Effects and C3 selection. Registry metadata determines which particle and lighting controls appear. The library uses an explicit preset selector with description and placement actions to keep 17 entries from pushing the selected inspector offscreen. Effect-light Apply is separate from visual Apply and discloses that light appearance participates in lighting scenes. Tests must cover every preset, parameter bounds and roundtrip, conservative fog support, emitter ownership/duplication/history/floor changes, scene compatibility, player commands/snapshots/reconnect, shader rendering/quality/cleanup, and existing map gestures. Physical tablet and private-map acceptance remain manual.

### 6.3B implementation and acceptance

Implemented 16 new presets (17 total with A motes): four fires; embers/falling/electrical sparks; column/drifting/thick smoke; vent/short-burst/plume steam; ground/cavern/magical mist. Parameters are finite and bounded: density .1–1, lifetime .25–10 seconds, spread .1–4 squares, vertical extent .1–8 squares and X/Z drift −1–1. Optional parameters default per registry; old A motes remain unchanged. Horizontal fog bounds are conservative at four times spread × scale, accounting for diagonal drift and camera-facing billboard corners; they do not depend on the current particle phase or quality tier.

Fire uses one instanced draw for 2/3 crossed shader flame planes (Low/Medium–High), with colour gradient, sway/flicker and optional bounded embers above Low. Smoke, steam and mist use 6/14/24 maximum instanced quads before density scaling; sparks use 12/32/64. All animation uses static seeded attributes and uniforms in the existing Fiber loop. Mist quads lie in the ground plane, limiting vertical spill. No texture assets, physics, postprocessing or per-frame geometry allocations are introduced. Each unique buffer/material is disposed on disable, deletion, parameter/quality replacement and unmount. Reduced motion keeps a static sample and stops ongoing invalidation.

Effect lighting is persisted in existing `lighting.sources`; effects store only the stable emitter reference. `map.effect.light.set` atomically creates/configures/removes ownership. Set updates floor/position, duplicate allocates a separate emitter, delete/floor removal removes it, floor duplication remaps it, and undo restores the complete record pair. Import validation rejects missing/shared/attached or displaced effect emitters. Direct source mutation cannot steal a managed emitter; standalone emitters remain unchanged. Light appearance is independent of visual intensity, and existing scenes capture/activate it normally. Disable/zero intensity gates the rendered and projected emitter without overwriting its saved appearance. **Owned lights snap to target when fog is enabled**: this prevents an old interpolated radius from crossing a newly concealed boundary. Ordinary lights retain the pre-existing transition policy. Default effect lights have no point shadows; existing global quality/shadow/flicker limits remain authoritative locally.

Player projection applies the same effect-support-plus-light-radius decision to both records, including legacy maps. A small-light regression verifies that the ordinary source anchor-cell filter cannot orphan an otherwise permitted effect-light pair. Concealed records never instantiate tall particles, selection geometry or point lights in Player Preview. Existing full-floor GLB visibility limits remain. Data already received by an authorized player cannot be made unknown by later concealment. No server authorization, fog mask, encounter statistics, map transition or unrelated saved lighting scene is changed by visual edits.
