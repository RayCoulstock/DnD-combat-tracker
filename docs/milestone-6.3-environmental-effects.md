# Milestone 6.3 — Environmental effects

## Phase 0: repository audit and design

Audited against origin/main `6eefe9c` (Milestone 6.2 session rejoining), before implementation. Canonical UI source is `docs/ui/ui-design-guidelines-v2.1.md` and `feature-zone-matrix.md`; the unversioned guidelines file does not exist. Read the 6.0 lighting and 6.1 fog architecture, current shared schemas/domain, editor surfaces, GLB resource leases, lighting renderer and commands, server persistence/command execution and CI configuration.

### Architecture and extension points

BattleMap3D owns one demand-rendered R3F Canvas. BattlefieldScene translates visible floors with northwest alignment and feet / 5 elevation. DungeonBuilder owns D4 tools, C3 contextual forms and D3 history. CellEditorSurface already converts pointer coordinates, snaps placement and supports tap without interfering with middle/right camera controls. SharedModel3D/modelResources lease cached GLBs; effects must not alter these assets. Shared `readDungeon`, `dungeonLevels`, `composeLevels`, `levelDocument` and `editMap` are the persistence/multi-floor/history boundaries. Map commands execute through DM-authorized `applyMapEdit` and existing server transactions, command receipts and encounter/map revisions. Templates/import/export all use the same strict map schema. No database migration or alternate command channel is needed.

### State and registry

Optional document-level `environmentalEffects: {version: 1, effects: [...]}`. Absence remains absent on legacy maps. At most 64 stable-ID records, bounded finite position (grid anchor X/Z and heightFeet), yaw degrees, scale, enabled, intensity, speed, colour and opacity. Floor IDs and in-bounds anchors validate against the actual map. No renderer objects or particle positions persist. Foundation introduces a bounded magical-motes preset to exercise the engine; B and C add their libraries only in their own increments. Registry metadata defines category, description, icon, defaults, accepted parameter schema, renderer key, local quality budgets, conservative animated bounding radius, resources, light/attachment capabilities. Client renderer registry is separate from shared metadata; no executable user code is accepted.

### Rendering, lifecycle and quality

One shader-driven Points draw per effect with deterministic static seeds; no per-frame React state, allocations, geometry replacement or network commands. Each renderer uses Fiber's existing useFrame/invalidate scheduling and disposes owned geometry/material on replacement/unmount. Low/Medium/High reuse the existing local lighting-quality preference, with 12/32/64 particles per foundation effect. Reduced motion renders static particles and stops continued invalidation. Disabled effects unmount. Visible floor groups own resource lifetime, so floor/map switches release inactive resources. B adds billboard atmosphere/flame adapters; C adds reusable animated surfaces and bounded arc geometry, rather than a giant preset conditional.

### Lighting and fog security

A does not emit light. B must integrate optional emitters into existing map-owned lighting sources, with explicit ownership and atomic cleanup; no independent Three lights. D attachments must reuse stable scene-object IDs and existing transform conventions; missing targets disable effects until reattached, with no dangling runtime references. Linked lights must follow the same visibility decision as their effect and cannot be double-owned.

Server `playerDungeon` filters effect records before serialization. Only player-visible floors and fully revealed conservative animated support are eligible. Radius includes every animated particle at every yaw/scale and height (A uses a sphere bound). Support crossing map bounds is withheld while fog is enabled. No effect names/private metadata or attachment IDs are needed in A. Hidden records never reach player raycasting, inspectors, geometry or reconnect snapshots. This intentionally withholds an entire effect at a partial boundary rather than clipping its particles. Existing GLBs require full-floor revelation when trusted footprint bounds are unavailable. Previously delivered data cannot be revoked from a player's memory/cache. Visual concealment alone is not data secrecy. Later attachments require parent visibility filtering before this support test.

### Synchronization and resource limits

Existing DM-only map commands provide atomic set, duplicate and remove. Existing map history, server campaign/session authorization, stale-revision rejection, receipts, persisted snapshots and reconnect joins remain authoritative. Only configuration changes travel over Socket.IO. Animation is local deterministic presentation, with no per-frame writes. D lifecycle commands must stamp authoritative start/revision data on the server and reconstruct final state for late joiners. No combat, terrain, fog-mask or transition mutation is introduced.

### Performance targets and measurement

Targets, not measured guarantees: desktop ~16.7ms / 30 active effects; tablet ~33.3ms / 10–15. Test 12×12/5, 30×30/15 and 50×50/30 scenes (the actual repository limit is 50, so the requested 60×60 requires a separately scoped map-limit change). Include multiple floors and fog/lighting/GLBs. Record average and p95 frame intervals, renderer.info calls/triangles/points/memory before placement, after steady rendering and after deletion/map switch. Use browser instrumentation only in development/tests; physical tablet measurements remain separate from Chromium software rendering. Foundation cap: 4,096 points / 64 effects at High; each effect owns one bounded buffer/material. Distance/frustum scheduling improvements belong to D after measurement.

### Migration and rollback

Additive JSON only; existing encounter_maps/template/checkpoint storage and backups include effects. Legacy maps are not rewritten. Document-level effects must be stripped from floor geometry adapters and explicitly retained by composition. Floor deletion removes effects; duplication uses deterministic new IDs and enforces capacity atomically. Floor shrink rejects out-of-bounds effects until moved/deleted. Old strict binaries reject the new field: preserve exports and coordinate binary rollback; never silently strip persisted effects. No production data or deployment changes.

## Delivery gates

A → B → C → D each start from updated origin/main, target main, pass required CI, merge, then wait for the publication workflow. Never deploy. Git fetch works in this environment, but GitHub API requests to api.github.com return Forbidden; PR creation/check inspection/merge are blocked until that access is configured. ## 6.3A implementation and review

The foundation preset is Magical motes. D4 Effects opens the existing C3 Selection section, with category browse, a placement action and keyboard-accessible centre placement. Existing square hover previews the location; click/tap places exactly one effect and returns to selection. Escape returns to Select. Gizmos select effects only in the active DM editor. C3 uses explicit Apply for appearance/position/yaw/height, retained drafts with changed-elsewhere feedback, duplicate and confirmed delete. Low/Medium/High share D5's existing local quality setting. Unsupported light and attachment controls are absent. No camera/canvas remount or permanent dock was added.

Strict shared schemas reject unknown presets/versions/fields, duplicate IDs, NaN/infinity and out-of-range parameters. Effects are document data, explicitly excluded from level geometry and retained through composition. Floor duplication remaps IDs; removal drops that floor's effects. Set/remove/duplicate use the existing history and DM authorization, transaction revisions and receipts. Renderer adapters remain separate from preset metadata and UI. One bounded shader Points buffer/material per enabled visible effect; buffers/materials dispose on unmount/quality replacement, reduced motion remains static. No added textures, lights, postprocessing, dependencies, rules or network animation state.

Security regression: tests caught and fixed the legacy single-floor early-return projection path as well as the multi-floor path. Both now filter before sending effect records. Under fog, complete conservative support must fit inside the revealed map region; an effect crossing the boundary is withheld as a whole. Unknown imported data is rejected, never executed. A has no attachment identities/private effect names to expose. B/C/D remain unstarted until A completes its required PR/CI/merge/publication gate.

Manual review checklist (not a claim of physical-device acceptance): place three motes in Warehouse, edit height/yaw/scale/colour, duplicate/delete/undo/redo; switch floors and save/reload; join a player and verify conceal/reveal; confirm existing camera, wall/terrain and fullscreen gestures. Test tap/pen on a physical tablet and inspect reduced-motion presentation. Actual private Warehouse/Myconid maps and physical tablet GPU profiling are not available in this environment.
