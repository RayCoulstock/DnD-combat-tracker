# UI/UX migration plan — proposed after Phase 0

**Baseline:** `0a2aedf`. **Prepared:** 31 October 2026. **Status:** Phase 0 complete; **Phase 1A/1B implemented following the user’s explicit approval**, with evidence in [Phase 1 foundations](phase-1-foundations.md). Later phases remain planned. No deployment is requested.

The goal is the proposal's visual hierarchy with every existing feature, data boundary, role and scene contract preserved. Use the [feature matrix](feature-zone-matrix.md) as a checklist and the [audit](ui-audit.md) as evidence. The [guideline addendum](ui-design-guidelines-v2.1.md#12-repository-backed-phase-0-corrections-proposed-for-review) resolves planning conflicts; it does not introduce APIs or domain features.

## 1. Reviewed planning defaults

| Decision | Recommended default | Consequence / approval boundary |
| --- | --- | --- |
| Shell/navigation | Reuse component-state navigation and one `Multiplayer` authority adapter initially | No new router, URL contract, Redux store or duplicate socket. Deep linking is later scope if requested. |
| Visual fidelity | Adopt palette/surface hierarchy, context placement and density targets; adjust contrast/target sizes | Do not adopt fixed body dimensions, mockup display spans or failing muted-text combinations as mandatory production code. |
| Save language | Encounter “Synced / Updating / Connection lost / Update not confirmed”; local draft “Apply”; reusable template “Save new template / Overwrite selected”; checkpoint and character state named separately | Retains current automatic encounter persistence and explicit library/campaign state. No generic global Save shortcut until context is specified. |
| Role recipes | Anonymous/invite, local, DM preparation/live and player waiting/live as in audit §4 | Player mode is not a hidden-button version of a full DM state tree. Preserve its existing Local tracker switch/return through A4 if A2 is omitted. Keep server projection and media grants. |
| Inspector | Existing draft owners retained; group presentational sections; allow E3/E4 for large calibration/import/settings forms | Auto-open only on relevant user selection/tool change, not every network revision. Define discard/reload/resolve conflict behaviour before lifetime changes. |
| Fullscreen | Keep expanded workspace and document-native fullscreen separate | Native dialog portals must remain accessible; keep restore, denial fallback, local view/scroll and inert state. |
| Roster | Visually consistent C1, but explicitly label encounter-wide versus active-floor scope | Do not change active turn on selection or accidentally move an off-floor token. Narrow Tracker gets a C1/B3 trigger, not only a D1 dock. |
| Destructive operations | Preserve existing confirmations; replace with accessible E4 where appropriate; agree exceptions for undoable editor gestures | No confirmation per erased square. Irreversible asset/file deletion, replacements, clear/restore/revoke must remain deliberate. |
| Proposed features | Unsupported blueprint items remain absent/reserved | Pause, temp HP, condition timers, player preview, rename encounter, history timeline, bulk campaign save, freehand draw and other matrix §10 items are separate features, not redesign completion criteria. |
| Preparation without live session | Keep existing account libraries without encounter; maps in a local or active DM encounter can be edited while not live | “No live session required” must not become a promise of a nonexistent standalone persistent map editor without any encounter context. |

The user authorized Phase 1 foundations and scoped presentation work. This does not authorize every later feature or route idea; retain these defaults for later phase review.

## 2. Invariants for every implementation PR

1. No schema/command/persistence changes merely to relocate controls. Preserve encounter version 1, legacy map normalization and current schema versions, IDs, stat-block imports, GLB references, portraits, conditions, initiative, active turn, positions and floor IDs. Preserve local map templates as data.
2. Keep existing REST/CSRF/role checks, command envelopes, revisions, command receipts, snapshot merging and rejoin behaviour. UI preference changes must not issue encounter commands or socket joins. Never buffer disconnected writes.
3. Keep DM/player media grants and explicit player projection. Do not introduce client-only authorization or cache private resources across role/account contexts. No UI preview receives a broader player payload.
4. Preserve the mounted renderer/camera for current supported panel, map/editor and fullscreen transitions; permit in-place responsive resizing. Do not key the renderer by dock, selection, revision or fullscreen. Tracker retention beyond today's unmount policy requires deliberate design rather than an incidental routing refactor.
5. Keep previews/drafts local until their existing explicit Apply/Accept/Share action. Library definition updates do not rewrite encounter instances; ordinary combat changes never silently save campaign state.
6. Preserve native dialog layering, focus/keyboard operation, pointer event isolation, Escape priority, touch cancellation and the ability to leave expanded/fullscreen mode.
7. No runtime import of `docs/ui/references/v2/concept.css`, mockup HTML or `mapbg.jpg`. No unnecessary dependencies, replacement Three.js loader, duplicate asset service or new authoritative browser store.
8. At each step retain an accessible replacement before removing an old entry point. Do not leave two active keyboard/focus targets for the same old/new control. Update matrix rows and screenshots in each UI-changing PR.

In particular, contextual Ctrl/Cmd+S and shared Next turn/Space need a deliberate target/activation policy.

## 4. Risk register

| Risk | Impact / trigger | Mitigation and proof |
| --- | --- | --- |
| R-CANVAS | Lost camera, GLB reloads, wrong square after resize or new route remount | Stable owner/keys; in-place resize; root/control identity tests; actual live-camera projection after measured readiness. Compare exact token/floor coordinates and model transforms. Aspect change itself is expected. |
| R-DRAFT | Drawer/accordion extraction or CSS `display` remount loses unsaved calibration, endpoint pick or scenery transform | Keep current draft maps/owners; explicit selection/revision keys; test hide/reopen and change floors with a draft, plus conflict/discard rules. |
| R-SECURITY | Shared E1/C3 displays concealed NPC/HP/AC or private library metadata to players | Render projected data only; positive and negative HTTP/WebSocket/media tests. Do not substitute CSS-hidden DM JSON for server projection. |
| R-SYNC | New shell duplicates subscriptions, writes stale encounter, loses omitted-map patches or buffers offline edits | Single Multiplayer adapter; stable snapshot refs and pending guard; no reconnect on UI toggles. Test activation/switch/late join/reconnect and command receipts. |
| R-SAVE | Generic Save implies durability while only a draft/template is changed; combat autosaves campaign HP unexpectedly | Separate state scopes and labels; assert correct command/API called and unrelated tables/instances remain unchanged. Explicit per-character state revision test. |
| R-FULLSCREEN | Inner-element native fullscreen hides body-portaled dialogs; inert leaves controls unreachable | Preserve document fullscreen and owner subtree; native dialog tests, denial fallback, keyboard exit, scroll/focus restoration, standalone player map path. |
| R-OVERLAY | Z-index/depth labels cover dialogs; flyout intersects dock or clicks paint a floor | Keep isolated canvas/native top layer; layout clamp; pointer guards; open one contextual surface; test no map revisions on form/menu gestures. |
| R-LOCALDATA | Treating all localStorage as preferences deletes local map-template data | Do not clear/rename template records in styling PRs. Guard storage errors; optional UI-key migration is versioned/idempotent with legacy read fallback and rollback. |
| R-ASSET | New picker/card disposes shared resources, resets transforms or exposes a private binary | Reuse scoped leases, independent clones and existing grants; textured GLB, preview/map coexistence, missing asset and account-switch tests. Request budgets are context-aware; previews have intentionally distinct scopes. |
| R-UPLOAD | Closing/reparenting forms aborts uploads or applies late responses to another entry/floor | Retain current cancellation/unmount guards; verify progress/cancel/error and that completion cannot assign an image/model to a new target unexpectedly. |
| R-KEYBOARD | Global Escape/Space/Save/Delete fires in fields, another hidden view or multiple layers | Active context registry after preservation tests; modal/typing/IME/modifier/repeat guards; layered Escape priority; native button Space behaviour preserved. |
| R-RESPONSIVE | Header/inspector widths or fixed docks cover map/roster at zoom/touch heights | Available-stage layout, explicit overflow priority and E3/E4 forms, no universal page scroll lock; verify sizes/zoom/safe areas and keyboard navigation. |
| R-CSS | Generic reference resets change unrelated forms or hidden player/local branches | Scope tokens/components and progressively remove only proven-redundant overrides; visual snapshots plus semantic/permission checks. |
| R-CI | Visible canvas exists before Fiber root/controls, or tests project via a synthetic initial camera | Keep existing readiness-polling helper and deterministic delayed-root regression. No sleeps or relaxed grid assertions. Use dedicated test accounts/database and fresh server per run/batch; observe auth rate-limit budgets rather than weakening production limits. |

### Required fixtures

- Legacy encounter JSON and legacy single-floor map; current multi-floor map with unequal dimensions, positive/negative elevation, locally hidden floor and independently player-hidden floor.
- Two persistent characters/NPCs, multiple instances of one monster template with different HP; library definition and campaign state with different HP/maximum HP; one tracker-only instance and one explicit duplicate override.
- Visible and hidden GLB miniatures/scenery/logical wall/door/transition models, a missing/deleted asset, floor-image variants and a textured GLB large enough to exercise original rendering/resource guards. Use synthetic existing fixtures, not private artwork.

- Local/shared ruler/template; player-owned and other-owned overlays; measurement rules and expiry; stale edits and disconnected state; image/generator previews and unapplied calibration/scenery/transition drafts.

## 6. Role × layout acceptance checklist

At minimum test desktop 1440×1000 and wider, 1280×900, 1024 landscape, 768 tablet, 390 phone and 320 minimum width, a short-height landscape case and **200% browser zoom**. DPR/device scale is not the same as browser zoom. Cover keyboard-only operation and a touch-emulated case automatically, plus real touch and screen-reader/native-fullscreen checks manually in supported browsers. Agree browser support before claiming cross-browser compliance.

For each touched recipe (anonymous, local, DM preparation, DM live, player waiting/live):

1. Navigate from entry to its permitted table/context. Verify account/campaign/view switch and sign-out/rejoin; no library access or secret content for players.
2. Exercise every touched matrix row from both its compact and expanded entry points. Preserve an equivalent in Tracker when canvas docks are absent. Check labels, long names, translated-length strings and error wrapping.
3. Open/close menus, drawer, entity controls and nested picker using pointer and keyboard. Verify focus return, topmost Escape, Enter/Space on the focused control, no shortcut in a text field, no accidental map/turn mutation and no background focus under a modal.
4. Pan/zoom, open/close inspector/roster, use map/editor toggle, expand/native fullscreen and restore. Same mounted root/control where promised; camera target/position remain unless a documented floor-follow/reset action changes them; aspect and projected coordinates update with real canvas size.
5. Switch floors with a draft; preview/calibrate an image; draw/undo/redo; place/duplicate/move models; pick both transition endpoints and travel with both overrides; verify local preview/visibility versus shared revelation. No unintended server update on cancel or local view changes.
6. Add a library monster twice and mutate one, add persistent character with saved/full state, prevent duplicate unless explicit, place on active floor and add tracker-only, explicitly save selected conditions/HP to campaign. Refresh/reload and verify default model/source identity/instance independence.
7. Join a second player and a late player; stop/start/switch encounter/reconnect/revoke. Confirm exact permitted state and narrow UI, no hidden geometry/stat/media leak and no full library broadcast. Open libraries/menus and confirm no extra socket connection or auto state save.
8. Export/import golden fixtures and save/load template copies. Compare supported semantic data and expected normalization/ownership policy, not cosmetic JSON byte order. Preserve local templates and server backups. No data migrations are needed by these UI phases.
9. Check visible focus, appropriate screen-reader roles/names/announcements, 40px touch baseline, normal-text contrast ≥4.5:1 (appropriate large-text/non-text thresholds separately), non-colour state cues, reduced motion and persistent recovery after failures. No essential action obscured by drawer, dock, virtual keyboard or truncated header.

## 7. Rollout, rollback and completion

Implement one surface/flow per PR; keep handlers and state owners as adapters until the replacement has passed its matrix rows. If a temporary switch is necessary, use one presentation path at a time without duplicate focusable controls; do not introduce permanent parallel UI frameworks or duplicate services. No feature-flag package is required.

Rollback is a normal code revert of the affected presentation PR. No UI phase should require a database rollback, media relocation or clearing localStorage. If a later independently approved feature requires a migration, it gets its own forward/backward-compatible plan and normal backup/release review. Preserve the current backup/deployment procedures and never deploy as part of this audit.

A PR description should list the matrix IDs moved, screenshots for relevant sizes/roles, data/state/permission invariants verified, automated commands and manual checks actually run, limitations and rollback. Do not mark a prototype as accessible or multiplayer-safe just because its desktop screenshot matches the concept.

**Review stop:** Phase 0 ends here. Approve or revise the proposed decisions and the first foundation PR's scope before beginning Phase 1. No redesign code, schema, dependency or deployment change is included in the Phase 0 deliverables.
