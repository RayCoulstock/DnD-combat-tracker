## Proposed A architecture

Optional map-owned, independently versioned fog record. Four binary samples per grid square in each axis; fixed-size lowercase hexadecimal bitset per stable floor ID. Missing floor entry means fully hidden. At 50×50, each floor needs 10 KB hex; twelve floors need at most 120 KB. Validation rejects malformed lengths, unknown floors, unsupported versions and invalid bounds. No pointer event history or cell meshes. Existing maps retain absent fog fields. Enable starts concealed; disable preserves masks; reset requires explicit confirmation and retains enable state. New/duplicated floors start concealed; rename retains masks; deletion removes masks. Resize resets that floor conservatively. Existing map revision/history/persistence handle fog atomically.

Server projection is authoritative. With fog on, procedural floor cells and ordinary objects are sent only when their complete conservative footprint is revealed. Walls use complete segment footprints, not centre points. GLB horizontal bounds cannot be inferred safely from existing height-normalised scale, so custom scenery/architecture/miniatures are conservatively withheld until their entire floor is revealed. This is a deliberate A limitation; follow-up metadata bounds can narrow it without disclosing binaries or trusting client geometry. Tracker combatant identity/initiative remains as established, but hidden map positions and model references are omitted; hidden map selection/hover/labels/inspector cannot instantiate them. Tactical overlays are withheld on partially hidden floors until authoritative footprint support exists. Hidden emitters are withheld and gizmos stay DM-only.

Uploaded battle-map files require a server-baked, fog-masked map-coordinate image for partial floors. The original file is not granted solely by that placement. Repeating textures are reusable materials; grants require projected references. Terrain strokes whose entire conservative support is not revealed are withheld in A, rather than broadcasting hidden stroke coordinates. Previously received information cannot be revoked from a player's memory/cache after conceal.

Rendering combines server-safe scene projection with one black, unlit masked plane per visible floor. All hidden objects are removed before rendering (including tall/large GLBs), rather than relying on that plane to cover their height. Revealed samples are clear; edge softness in C darkens only inside revealed space. DM editing sees the full scene, with optional boundary overlay. DM Player Preview uses the same projection as player snapshots and blocks map edits. Floor elevations/stacking retain independent masks and northwest alignment. Transition records require both endpoints/floors revealed; travel never changes fog.

Player map omission caching must not reuse projected maps based solely on mapRevision: moving an attached emitter can change projected map content during a combat revision. Fog-enabled player snapshots therefore include authoritative projected maps. No camera or combat changes are made by fog operations.

## 6.1A implementation and compatibility

Implemented optional `fogOfWar` version 1 without changing existing map schemaVersion or adding SQL tables. Commands: `map.fog.enabled`, `map.fog.reset` (literal confirmed flag), `map.fog.mask` (complete bounded floor mask). Foundation mask writes are the atomic adapter for B's completed gestures. Undo restores exact bytes through existing bounded history. Fog commands preserve combat/tactical/lighting objects rather than running geometry reconciliation unnecessarily. Projection strips hidden placement/model data while retaining existing initiative records and permitted tracker information.

`server/fog-image.ts` bakes partial uploaded artwork into map coordinates using the existing floorImageUv calibration. Transparent hidden pixels contain zero RGB as well as zero alpha. It produces at most 800×800 pixels (16 per square); full-floor revelation returns the original calibrated image. Two simultaneous mask jobs per process bound decoding work; extra requests return a retryable 429. Responses are private/no-store and verify live membership, session, current encounter and projected floor access. Player direct original-image grants require an unmasked public placement or public material reference. Reusing battle-map artwork itself as a repeating material intentionally authorizes that shared material's contents; use separate texture assets. Revealed full files already downloaded cannot be recalled on conceal. Retrying a stale fog URL always bakes current authoritative state; browser resource keys use monotonic mapRevision rather than undoable fog revision.

One DataTexture and plane per displayed floor, no cell meshes. Textures are disposed on replacement/unmount. Server projection handles full object support before instantiation, so geometry height does not defeat concealment. The DM's optional overlay is translucent and disabled by default. Player Preview suppresses editing controls/callbacks/keyboard shortcuts and uses the same projected map, placements, lights and overlays as player snapshots. D4 opens C3 settings; reveal/conceal gestures remain B.

### Explicit A limitations and follow-up work

- Custom GLBs (including miniature and architectural models) require full-floor revelation in A because trusted horizontal bounds are absent from asset metrics. A room-only reveal therefore withholds those models. This must be resolved before claiming the supplied Warehouse/Myconid room-reveal scenarios complete. Smallest compatible follow-up: capture trusted geometry bounds during existing server asset validation and apply the same height-normalisation/calibration transforms in shared visibility projection. Existing assets need conservative fallback or revalidation.
- Partial terrain strokes are withheld until their entire brush support is revealed. Shared tactical overlays require a completely revealed floor. Nothing is deleted from authoritative state. B/C should replace these conservative policies with clipped derived masks and bounded footprint-aware overlays.
- Boundaries are binary at quarter-square resolution in A; edge softness is versioned state reserved for C and currently renders hard edges. No animation is implemented. Partial artwork is downsampled to 16 pixels per square. These are reviewable foundations, not a claim of finished cinematic quality.
- Fog-enabled players receive full projected map snapshots, including on combat-only revisions; C can optimise using an equality/hash of the complete projection rather than mapRevision alone. Geometry reuse remains active on receipt.
- The tracker intentionally retains already-public combatant identity/initiative and permitted details. Fog protects map placement and private map content, not established tracker disclosures. Previously authorised data cannot be made unknown by concealing it later.
- No real Warehouse/Myconid private artwork or physical tablet testing has been performed. A synthetic warehouse, actual textured GLB and independent browser contexts exercise the same boundaries.

### Performance evidence

Cloud CPU benchmark (`work/fog-benchmark.ts`, scratch only): twelve 50×50 floors, 30,000 floor cells and 30,600 wall segments; 120,260 bytes fog JSON. Thirty projections: median 44.94 ms, p95 83.88 ms while other checks were running. A 2048×2048 input baked into the partial 800×800 map image in 208.73 ms, producing 12,314 bytes. These are CPU/container measurements, not browser FPS or tablet GPU promises. Work happens on snapshots/edits, not every frame. Per-player worst-case projection and large full snapshots are material costs for C to reduce. Existing history limits can retain fewer than twenty frames on very large maps; fog does not raise those limits.

## 6.1B — editing tools architecture

B builds on the accepted A foundation, merged through PR #47 at `1827c6e`. D4 Fog gains an existing Menu flyout; C3 owns the settings, floor actions, accessible polygon completion/cancellation and save feedback. D3 stays unchanged. One active `fog` editor tool uses a dedicated EditorSurface adapter alongside existing terrain/drawing adapters, not a second Canvas. Left mouse, pen and single-touch paint; middle/right and two-touch retain camera control. Escape, blur, capture loss, a second touch, floor/tool/config changes and preview cancel unfinished work. Polygon completion is an explicit C3 button; dragging never adds a vertex. Maximum 64 polygon vertices; invalid/self-intersecting shapes stay local with an error.

Mask arithmetic uses the existing quarter-square binary raster. Brush segments rasterise capsules analytically, so sparse pointer samples cannot leave gaps. The client maintains a bounded draft mask, not an ever-growing event list. Rectangles use continuous coordinates with optional grid snapping and reverse-drag normalisation. Polygon edges/vertices have a local outline and draft masks are visual only. Each completed gesture sends one existing `map.fog.mask` command and creates one existing bounded undo frame. No command on pointer movement and no scene rebuild.

B extends the mask command with an optional expected prior mask and captured map revision. The editor always supplies it; the server rejects a stale gesture rather than overwriting intervening reveals (including a snapshot received before React has rendered it). These guarded edits also require fog to remain enabled. Payload is bounded at two 10 KB masks plus revision metadata per largest floor; legacy A mask commands remain compatible. Exact mask history and map revisions stay in existing owners. Whole-floor reveal/conceal uses the same adapter; Reset current floor uses the existing confirmed reset command. Existing A GLB/terrain/tactical conservative policies remain visible limitations; B does not claim C's cinematic animation or softness rendering. C3 shows the saved edge-softness setting/preview and explains its current hard-edge rendering.

B cancellation additionally keys the local gesture adapter by authoritative mapRevision. This prevents painting with an old coordinate frame if a concurrent floor addition/replacement changes the aligned world origin. A map revision received during a draft cancels it conservatively; ordinary camera controls are local and do not create revisions. The Scene and camera remain mounted: only the transient gesture adapter is reset. Single-touch and pen use native pointer capture; captured coordinates intersect the active floor with the current ray rather than reusing a stale object hit point. Middle/right polygon camera gestures preserve vertices; a second touch cancels unfinished work before camera input.

### B implementation and practical limits

New source owners: `shared/fogEditing.ts` (bounded raster arithmetic and polygon validation), `src/FogEditorSurface.tsx` (gesture capture, floor-ray mapping, outline/cursor and local draft), `src/fogEditor.ts` (typed local controller), `src/FogOfWarPanel.tsx` and `src/fog-tools.css` (C3 form). `DungeonBuilder` adapts these to the existing map command/history path; `DungeonScene.EditorSurface` selects the one active gesture adapter. The DM's normal fog overlay is replaced by the local draft overlay only while the fog tool owns input, avoiding double darkening. Preview uses only the authoritative mask.

No-op strokes/whole-floor writes add no history. Complete brush capsules prevent gaps even for a long single pointer segment. Rectangle draft masks are recomputed from the starting mask on drag, so reversing/shrinking does not leave draft trails. Polygons support concavity and either winding, and reject self-intersections, nonadjacent touching edges, duplicate/degenerate vertices, invalid coordinates and more than 64 points before mutation. Brush radius is 0.25–12 squares. Quarter-square binary boundaries and the A media/object policies remain unchanged. This does not implement C's softness or animation, vision rules or movement-driven exploration.

At the largest supported 50×50 floor, the draft uses a fixed 10,000-byte nibble array and serializes to 10,000 characters; a guarded command with both masks is approximately 20.1 KB. Pointer samples do not accumulate. Each displayed draft uses one fog texture/plane; replaced textures are explicitly disposed by the existing A component. Existing map history remains limited to 20 frames / 2 MB per direction, so large maps can retain fewer entries. A 64-vertex outline uses one bounded line and vertex markers, not fog-cell meshes.

Cloud CPU sample (100 brush steps per radius, including serialization): radius 1.5 squares median 0.47 ms / p95 1.30 ms; radius 6 median 0.52 ms / p95 1.07 ms; radius 12 median 0.69 ms / p95 2.73 ms. One 64-vertex large cavern polygon rasterized in 22.83 ms. This excludes DOM, raycast and GPU work and is not a tablet FPS claim. Native Chromium-emulated touch and pen, a two-touch cancellation and repeated GPU texture counts are automated; physical-tablet acceptance remains manual.

Proposed C changes: optional backward-compatible cinematic settings (default enabled, 750 ms, bounded 0–2000 ms), a DM-only settings command through existing map history, and a server-generated commit timestamp for completed fog masks. No pointer frames or animation frames are synchronized. A single reusable RGBA mask texture per floor stores authoritative concealment plus start/target visual opacity. Derived boundary opacity darkens only the authorized side; hidden samples always force opaque black. Two bounded CPU opacity buffers and one running interpolation replace any animation queue. On another operation, sample the current visual field once and retarget, immediately clamping newly concealed samples. A first mount, map/floor context change, expired transition, reduced motion, disabled animation or zero duration snaps to the authoritative state. Frame work mutates one uniform and invalidates the demand renderer, without React state or texture allocation.

Security policy: concealment is immediate, including mixed operations and reset/undo. A gradual conceal would require retaining withdrawn scene/media data, so the explicitly permitted secure fallback is used. Reveal animation only delays the presentation of already authorized floor content. Labels and objects use the authoritative server policy, not interpolated opacity; newly authorized tall objects can appear immediately at commit. Unknown-bounds GLBs continue to require a fully revealed floor; walls require their full conservative support. This is a documented visual limitation, not permission to centre-test large models. Filtered-out objects cannot cast player shadows. Light emitters use their full one-square support, existing explicit parent visibility and placement checks; authorized offset emitters may be sent as detached resolved lights without disclosing a fog-hidden parent. No map mask depends on illumination, movement or lighting scenes.

Snapshots remain the authoritative reconnect mechanism. First mount never replays historical transitions. Transition metadata contains no previous mask, hidden object, floor list or animation frames. Existing projected maps/media grants and tracker identity disclosures remain unchanged. Previously authorized data cannot be recalled from clients; original A GLB/terrain/image-resolution limitations remain explicit. The actual Warehouse/Myconid private maps and physical tablet are unavailable here; synthetic maps, real GLBs and browser touch emulation cover automated checks, with manual acceptance below.

### C implementation, security and lifecycle

`shared/fog.ts` adds optional `cinematic:{enabled,durationMs}` and optional `transition:{startedAt}` to version 1. Missing cinematic settings resolve to enabled / 750 ms; old maps remain unchanged until fog is enabled. Existing arbitrary 0–1 softness values still load; the new settings command accepts the three UI presets 0 / 0.5 / 1. Duration is a validated integer 0–2000 ms. Strict readers from older releases reject newly saved cinematic fields: release frontend/server together and retain exports before rollback. No database migration, dependency, service or second synchronization path is introduced.

`map.fog.settings` is DM-only through `applyMapEdit`, bounded history and the existing transactional revision/receipt path. It requires previously initialized fog and never enables fog implicitly. Mask commits stamp their time inside the shared authoritative edit function, not from a client-supplied timestamp. The single stamp plus fog revision and map-owned settings synchronize transition metadata; it contains no former mask or object information. Reset/settings/toggles clear the stamp. Undo/redo restore exact saved frames; expired stamps snap. Client/server clock differences can shorten a visual transition or snap it, but never affect authoritative visibility or extend the configured maximum. No per-frame commands or snapshots are generated by fog animation.

`src/fogAnimation.ts` owns bounded mutable opacity/packed-mask arrays and a cached two-pass chamfer distance field. `src/FogOfWar3D.tsx` reuses one linearly sampled RGBA texture per mounted floor. Shader sampling reads authoritative concealment at the exact texel centre (unfiltered); concealed pixels force opacity 1 regardless of interpolation, exposure or edge treatment. With softness Off, visual samples also use exact texel centres; Subtle/Soft interpolate only visual opacity and darken up to approximately 0.375 / 0.75 squares inside the revealed side. No geometry is authorized by a soft boundary. No mipmaps, cell meshes, per-frame uploads or React animation state. The unlit black material does not depend on lighting. Disposal runs on context/dimension changes and unmount; one active-floor context switch snaps all mounted floor resources. Map/floor IDs, dimensions and preview/overlay mode isolate animation contexts without remounting the renderer or camera. Draft editing overlays are immediate.

A running reveal retargets from its sampled visual opacity when another completed mask arrives. Newly concealed pixels clamp immediately, even in mixed edits. Reconnect, refresh, first mount and returning to a floor display its current target rather than replaying history. Live reduced-motion changes stop ongoing interpolation. Demand rendering requests frames only while interpolation is active; normal camera/flicker retain their existing owners. Low/Medium/High use the same inexpensive two texture lookups, with no additional shadow or renderer requirements.

Player scene construction uses the existing server projection, so hidden models, walls and tokens are absent from both main and shadow rendering. Fully supported walls render normally; a wall crossing an unrevealed sample is withheld as a whole. Unknown-bounds GLB architecture/scenery/miniatures still require the entire floor revealed. This is deliberately conservative and means partial-room GLB reveals in the private manual scenarios cannot yet be claimed. The smallest future mitigation is trusted conservative model bounds captured during server validation (including animation/morph/skin support), plus revalidation of old models; this milestone does not introduce an unsafe centre test. Partly intersecting terrain strokes and tactical overlays retain A's documented gates.

Emitters require their entire one-square support in a revealed region and a player-visible floor. Explicitly invisible, missing or unplaced parents still suppress attached emitters. An offset emitter with authorized support can remain lit even if its visible-but-fog-hidden parent is withheld. For fog-enabled player projection all such sources are detached at their resolved world position, with a generic name and no attachment reference/offset. Subsequent server snapshots update those resolved positions, so attached lanterns still follow movement without granting the parent. Lights whose support crosses the boundary are withheld; other permitted lights can naturally illuminate visible geometry across a boundary. Concealed geometry/casters are absent, so this spill cannot disclose their silhouettes or shadows. Stacked floors retain 6.0's shared atmosphere/light-spill limitation; no per-floor light isolation is claimed. Point lights, attachments, flicker and lighting presets never write fog, and fog commands preserve lighting exactly.

Privacy remains server projection plus media authorization, not a promise based on the shader. Player snapshots exclude fog-hidden object definitions, placements, model references, private light attachments and hidden floors using A's existing policy. Tracker roster identity/initiative behavior remains intentionally public as before. ### C measured performance

Cloud CPU benchmark, 50×50 floor / 40,000 raster samples, 100 alternating whole-floor commits after warm-up with Soft boundaries: median **1.47 ms**, p95 **1.85 ms** for field derivation/retargeting. 100,000 progress samples took **2.21 ms** total. This measures CPU field work, not DOM, raycasting, GPU frames or tablet FPS. Persistent CPU arrays total **400,000 bytes per maximum floor**, packed texture **160,000 GPU bytes** (excluding driver overhead); twelve mounted maximum floors therefore use about 4.8 MB CPU / 1.92 MB texture storage. No per-frame texture allocation/upload and no animation queue. Browser tests inspect stable texture identity across edits/quality changes; B's repeated-painting GPU bound regression remains included. Full projected snapshots, conservative media baking and existing A projection costs remain unchanged rather than being disguised by the animation measurements.
